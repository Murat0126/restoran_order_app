# Деплой QR-меню (production / staging)

Эта инструкция объясняет, как поднять систему так, чтобы **гость
с улицы открыл QR-меню на своём телефоне и сделал заказ**.

Главное правило: и backend (Dart Frog), и frontend (Flutter Web)
работают **с одного адреса и одного порта**. Это упрощает CORS,
WebSocket, mixed-content проверки браузера и URL в QR-коде.

---

## Что делает скрипт `scripts/build_and_run.ps1`

1. Собирает Flutter Web: `flutter build web --release --base-href "/"`.
2. Копирует результат в `server/public/`.
3. Запускает `dart_frog dev --port 8765`.

Результат: по адресу `http://<хост>:8765/` отдаётся QR-меню, по
`/api/*` — REST API, по `/ws` — WebSocket, по `/api/qr/<token>.png` —
картинка QR-кода для печати, по `/api/admin/qr-poster` — печатный
лист со всеми кодами.

> Один порт, один адрес — никаких CORS-вопросов и mixed-content
> предупреждений в браузере.

---

## Сценарий 1 — Wi-Fi заведения (быстрый старт)

Подходит, если:
- сервер уже стоит в зале (ноутбук, мини-ПК, NUC, Raspberry Pi);
- гость подключается к вашему Wi-Fi (бесплатный гостевой или с паролем
  на чеке).

### Шаги

1. **Узнайте локальный IP сервера.** На сервере открыть PowerShell:
   ```powershell
   ipconfig | Select-String "IPv4"
   ```
   Запомните адрес вида `192.168.0.50`. Он должен быть **статическим**
   (закрепите на роутере по MAC, иначе после перезагрузки он сменится
   и все QR-коды перестанут работать).

2. **Откройте порт в фаерволе** (один раз, от Администратора):
   ```powershell
   ./scripts/open_firewall.ps1 -Port 8765
   ```

3. **Соберите и запустите**:
   ```powershell
   ./scripts/build_and_run.ps1
   ```

4. **Проверьте с телефона** (подключён к тому же Wi-Fi):
   - Откройте в браузере телефона: `http://192.168.0.50:8765/`
   - Должна загрузиться страница QR-меню.
   - Если попросит токен — в URL добавьте, например, `?t=<любой токен из БД>`
     или зайдите через `/api/admin/qr-poster` и нажмите QR глазами /
     прямо тапнув на изображение.

5. **Распечатайте QR-стикеры:**
   - Откройте на компьютере в браузере: `http://192.168.0.50:8765/api/admin/qr-poster`
   - Нажмите `Ctrl+P` → «Сохранить как PDF» или сразу печать.
   - QR-коды на стикерах автоматически зашиты с правильным IP сервера.

### Подводные камни Wi-Fi-сценария

| Проблема | Решение |
|---|---|
| iPhone Safari отказывается грузить страницу по HTTP. | Бывает, если сертификат компьютера странный. Обычно работает; если нет — переходите к Сценарию 2 с HTTPS-туннелем. |
| Гость не хочет подключаться к Wi-Fi. | Печатайте пароль рядом с QR; или используйте Сценарий 2 — там Wi-Fi не нужен. |
| IP сервера изменился — все QR не работают. | Зафиксируйте IP в DHCP-резервации на роутере. Или используйте mDNS-имя `restaurant.local` (если оборудование поддерживает). |
| Wi-Fi моргнул — гость в недоумении. | Будет решено offline-режимом QR-клиента (отложено). |

## Сценарий 2 — Cloudflare Tunnel (HTTPS, без публичного IP)

Подходит для большинства реальных установок: бесплатно, не нужен
белый IP/домен/сертификат, работает по мобильному интернету гостя
(без подключения к Wi-Fi). Бонусом — директор сможет видеть отчёты
с домашнего телефона.

### Шаги

1. **Скачайте `cloudflared.exe`** с официального сайта
   `https://github.com/cloudflare/cloudflared/releases` и положите
   в `C:\Tools\cloudflared\cloudflared.exe`.

2. **Залогиньтесь в Cloudflare** (нужен бесплатный аккаунт):
   ```powershell
   cloudflared tunnel login
   ```
   Откроется браузер — выберите свой домен (если есть) или
   воспользуйтесь стандартным `*.trycloudflare.com`.

3. **Тест без аккаунта** (одноразовый эфемерный URL — для проверки):
   ```powershell
   cloudflared tunnel --url http://localhost:8765
   ```
   В выводе появится строка вроде:
   ```
   https://random-words-1234.trycloudflare.com
   ```
   По этому адресу ваш сервер уже доступен из интернета по HTTPS.
   QR-коды, сгенерированные при запросе через этот URL, тоже
   автоматически получат этот адрес (см. в `/api/qr/<token>.png`
   логика `X-Forwarded-Host`).

4. **Постоянный туннель с фиксированным URL** (для продакшна):
   ```powershell
   cloudflared tunnel create restaurant-pos
   cloudflared tunnel route dns restaurant-pos menu.example.com
   cloudflared tunnel run restaurant-pos
   ```
   Теперь `https://menu.example.com` всегда указывает на ваш локальный сервер.

5. **Перегенерируйте QR-стикеры**, чтобы они вели на новый URL:
   - Откройте: `https://menu.example.com/api/admin/qr-poster`
   - Распечатайте.

### Что это даёт

- Гость сканирует QR → открывается `https://menu.example.com/?t=...` →
  работает с **мобильного интернета**, не нужно подключение к Wi-Fi.
- Все WebSocket'ы автоматически переходят на `wss://` — браузер счастлив.
- Можно безопасно расшарить директору доступ к админке.

## Сценарий 3 — свой домен и сертификат (опционально)

Если у заведения уже есть свой публичный IP и домен — поставьте
nginx/Caddy как reverse-proxy перед `dart_frog`, выпустите Let's
Encrypt-сертификат. Конфигурация выходит за рамки этого документа,
но любая стандартная инструкция «nginx + acme.sh + websocket proxy»
сработает.

Главное: пробросить `Host`, `X-Forwarded-Proto`, `X-Forwarded-Host`,
`Upgrade`, `Connection` — без них WebSocket и автогенерация base-url
для QR работать не будут.

## Чек-лист «всё ли работает»

После запуска прогоните:

- [ ] Открыть `http://<host>:8765/` в браузере компьютера — видна страница меню.
- [ ] Открыть `http://<host>:8765/api/menu` — JSON с категориями и блюдами.
- [ ] Открыть `http://<host>:8765/api/admin/qr-poster` — видны QR для всех столов.
- [ ] Сохранить любой QR как картинку и распечатать.
- [ ] Отсканировать камерой телефона — открывается меню в браузере.
- [ ] На телефоне добавить блюдо в корзину, отправить предзаказ — успех.
- [ ] Запустить smoke-тест: `dart run packages/api_client/bin/smoke.dart http://<host>:8765` — все 9 шагов проходят.

## Защита (минимум для продакшна)

Сейчас сервер не защищён, потому что это рабочий прототип. Перед
выводом в эксплуатацию **обязательно**:

1. **Сменить пароли пользователей** (по умолчанию `admin / 1234`).
   Поднимите переменную `ADMIN_PASSWORD` перед первым запуском
   или поменяйте через миграцию.
2. **Защитить `/api/admin/*`** — сейчас постер открыт без авторизации.
   Перед deployment добавьте проверку `requireAuth(roles: {admin})`.
3. **Перенести БД в защищённое место** (не `C:\` без шифрования).
4. **Регулярные бэкапы** SQLite-файла `.data/restaurant.db`.

Эти задачи учтены в основном TZ (Спринт 9, безопасность).

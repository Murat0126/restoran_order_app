# Техническое задание

**Проект:** POS-система для ресторана (Restaurant POS)
**Версия документа:** 0.1 (draft)
**Дата:** 2026-06-02

---

## 1. Назначение системы

Полноценная **система обслуживания в ресторане** (Point of Sale + Kitchen Display + клиентское меню), работающая по **локальной сети заведения** без обязательной зависимости от интернета.

Цель — заменить «листочки и устные команды на кухню» цифровой инфраструктурой, в которой:

- клиент сам видит меню по QR и может оформить предзаказ,
- официант принимает заказ на планшете и отправляет на кухню одним нажатием,
- кухня сразу видит блюдо на табло и получает печатный чек,
- касса в любой момент видит актуальные заказы и проводит оплату,
- администратор управляет меню, столами, сотрудниками и видит отчёты.

---

## 2. Стейкхолдеры и роли пользователей

| Роль | Что делает | На каком устройстве |
|---|---|---|
| **Клиент** | Сканирует QR на столе, смотрит меню, оформляет предзаказ | Свой смартфон (браузер) |
| **Официант** | Принимает гостей, формирует заказ, отправляет на кухню, доносит готовое | Планшет/телефон |
| **Кассир** | Видит активные заказы, формирует чек, принимает оплату | Стационарный планшет на стойке |
| **Повар** | Видит очередь блюд на табло, отмечает «в работе» / «готово» | Большой экран на кухне |
| **Администратор** | Управляет меню, столами, пользователями, смотрит отчёты | Любое устройство |

```

│                    Локальная сеть ресторана                   │
│                                                              │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐  ┌────────┐  │
│  │  Клиент    │  │  Официант  │  │   Касса    │  │  KDS   │  │
│  │ (браузер)  │  │  (Flutter) │  │  (Flutter) │  │(Flutter)│ │
│  └─────┬──────┘  └─────┬──────┘  └─────┬──────┘  └────┬───┘  │
│        │ HTTP          │ HTTP+WS       │ HTTP+WS      │      │
│        └───────────────┼───────────────┼──────────────┘      │
│                        ▼                                     │
│                ┌──────────────────────┐                      │
│                │  Локальный сервер    │  <- Dart Frog        │
│                │  (Mini-PC / NUC)     │     SQLite           │
│                └──────────────────────┘     WebSocket         │
│                                                              │
│  ┌──────────────────────┐    ┌─────────────────────────┐    │
│  │ Bluetooth-принтер на │    │ Bluetooth/Сетевой принтер│    │
```

**Ключевая идея:** один сервер в LAN держит всё состояние, все клиенты подключаются к нему и получают real-time обновления через WebSocket.

## 4. Модули системы

Проект делится на **5 модулей**.

### 4.1. Backend-сервер (`server/`)

| Подмодуль | Описание |
|---|---|
| REST API | CRUD заказов, меню, столиков, оплат, пользователей |
| WebSocket | Real-time события всем клиентам |
| База данных | SQLite со схемой и миграциями |
| Авторизация | Bearer-токены, bcrypt-хеши паролей, роли |
| Печать | Очередь печати с retry |
| Резервные копии | Авто-экспорт БД раз в смену |
| Отчёты | Z-отчёт, выручка по официантам, по способам оплаты |

### 4.2. POS-приложение (`lib/` → переименуем в `apps/pos/`)

| Экран | Кто видит | Описание |
|---|---|---|
| Логин | все | По username/password или PIN |
| Выбор зала | официант, кассир | Если залов >1 |
| Сетка столиков | официант | Цветовая индикация: свободен/занят/счёт |
| Меню + корзина | официант | Категории, поиск, qty, модификаторы, заметки |
| Детали заказа | официант, кассир | Позиции с курсами, «Отправить на кухню» |
| KDS (табло кухни) | повар | Карточки тикетов, приоритет по таймеру, цвета, звук, +/- статус |
| Касса — активные заказы | кассир | Список, фильтры, поиск по столу |
| Касса — оплата | кассир | Расчёт, скидки, разделение чека, способ оплаты |
| Профиль и выход | все | Смена PIN, выход |
| Админка — меню | админ | CRUD блюд, категорий, модификаторов, доступности |
| Админка — столы | админ | CRUD залов и столов, регенерация QR-токенов |
| Админка — сотрудники | админ | CRUD пользователей, смена паролей, ролей |
| Админка — отчёты | админ | Выручка, продажи блюд, средний чек |

### 4.3. Клиентское QR-меню (`client_menu/`)

| Экран | Описание |
|---|---|
| Меню | Категории, блюда, цены, добавление в корзину |
| Корзина | Изменение qty, комментарии, заметка к заказу |
| Отправка | «Спасибо, официант скоро подойдёт» |
| Статус заказа *(опц.)* | Клиент видит, что повар начал готовить / готово |
| Вызов официанта | Кнопка «позвать» — на планшете официанта индикация |
| Оплата онлайн *(опц., вторая фаза)* | QR-эквайринг (банковский) |

### 4.4. Печать чеков

| Шаблон | Содержит | Куда |
|---|---|---|
| Производственный чек (kitchen ticket) | Стол, время, состав без цен, заметки | Кухня |
| Барный чек | Напитки отдельно | Бар |
| Предварительный счёт | Состав с ценами, итог | Стол клиента |
| Фискальный чек *(если требуется)* | По 54-ФЗ или местным правилам | Касса |
| Перепечать | По id заказа | По требованию |

### 4.5. Real-time синхронизация (WebSocket)

| Событие | Триггер | Кто реагирует |
|---|---|---|
| `preorder.created` | Клиент через QR оформил заказ | Официанты (подтверждение) |
| `order.updated` | Изменения в заказе | Все, кто видит этот заказ |
| `order.sent_to_kitchen` | Официант отправил | Касса (счётчик активных) |
| `kitchen.item_added` | Появилась позиция на станции | KDS (звук, печать) |
| `kitchen.item_status` | Повар нажал «в работе»/«готово» | Официант (несёт) |
| `table.status_changed` | Статус стола изменился | Все экраны зала |
| `order.paid` | Кассир провёл оплату | Все (стол освобождается) |
| `waiter.called` | Клиент позвал официанта (с QR) | Все официанты этой зоны |
| `printer.failed` | Принтер не напечатал чек | Касса/админ (бейдж тревоги) |

## 5. Функциональные требования

### 5.1. Сценарий «Гость пришёл в зал»

1. Хост сажает гостя за столик; **или** клиент сам сканирует QR на столе.
2. Если через QR: клиент видит меню, оформляет предзаказ → официанту приходит `preorder.created`.
3. Официант на планшете открывает столик → если есть предзаказ, видит его, может отредактировать.
4. Официант добавляет/убирает позиции, отправляет на кухню («Отправить»).
5. На KDS появляется тикет, звенит звук, принтер выезжает чеком повару.
6. Повар отмечает «в работе» → «готово». Официанту приходит уведомление.
7. Клиент попросил счёт → официант нажимает «Счёт», заказ переходит к кассиру.
8. Кассир выбирает способ оплаты, проводит оплату, печатает чек.
9. Стол освобождается, заказ архивируется.

### 5.2. Особые сценарии

- **Разделение чека (split bill)** — кассир может разделить один заказ на несколько чеков (по гостям, по позициям).
- **Отмена позиции** — официант/админ может отменить позицию с указанием причины; событие логируется.
- **Скидка** — на позицию или на весь заказ; промокод (вторая фаза).
- **Сервис-сбор** — настраиваемый процент.
- **Перенос стола** — заказ переезжает со стола А на стол Б.
- **Перепечать чека** — по любому заказу из истории.
- **Повторение позиции** — «ещё пиво для стола 3» одним кликом.
- **Курсы подачи (courses)** — пометить блюдо как «вторая подача»; кухня видит сначала курс 1, потом курс 2.
- **Закрытие смены** — Z-отчёт, выручка по сменам, инкассация наличных.

## 6. Нефункциональные требования

### 6.1. Производительность

| Операция | Целевое время |
|---|---|
| Открытие экрана столиков | < 500 мс |
| Отправка заказа на кухню → событие на KDS | < 300 мс |
| Печать производственного чека | < 5 сек |
| Одновременных подключений к серверу | 30+ |
| Размер заведения | до 50 столиков |

### 6.2. Надёжность

- **Оффлайн-режим**: при разрыве сети с сервером клиент кэширует действия и синхронизирует при восстановлении.
- **Очередь печати с retry**: если принтер недоступен, чеки печатаются автоматически после восстановления.
- **Авто-перезапуск сервера**: Windows-сервис / systemd-unit, который поднимает процесс при падении.
- **Резервная копия БД**: автоматический экспорт раз в час + при закрытии смены, хранение последних 30 копий.
- **Целевой uptime**: 99.5% в часы работы заведения.

### 6.3. Безопасность

- Пароли — bcrypt с cost 12.
- Bearer-токены в `flutter_secure_storage` (на сервере — таблица `sessions`).
- Роли с проверкой на сервере для каждого endpoint.
- HTTPS опционально (для LAN не обязательно; для удалённого админ-доступа — обязательно).
- Логирование всех изменений заказов (audit trail).
- Защита от случайной отмены — двойное подтверждение.

### 6.4. Локализация и регион

- Основной язык: **русский**.
- Валюта: настраиваемая (по умолчанию `KGS`, поддержка `RUB`, `KZT`, `USD`).
- Дата/время: `intl` с локалью.
- Часовой пояс: настраивается в админке.

### 6.5. UI/UX

- Material 3, светлая и тёмная темы.
- **Адаптивность**: рабочее место на планшете (10″), касса на планшете или ПК-моноблоке, KDS на ТВ (24+″).
- Большие тач-таргеты (44+ px).
- Чёткие статусы загрузки/ошибок.
- Глобальный обработчик ошибок (Sentry или аналог).

### 6.6. Эксплуатация

- Установка на офисный мини-ПК (Intel NUC / Mini PC) с Windows 10/11.
- Принтер кухни — Bluetooth или сетевой ESC/POS.
- Принтер кассы — Bluetooth.
- Wi-Fi-роутер с покрытием всего зала.

## 11. Что НЕ входит в проект (out of scope)

Чтобы избежать раздувания скоупа, прямо фиксирую, чего не делаем в этой итерации:

- **Программа лояльности / бонусы / скидочные карты** — отдельная подсистема, позже.
- **Доставка / самовывоз** — не покрываем, только in-room.
- **Складской учёт (ингредиенты, списания)** — отдельный проект.
- **Бухгалтерия, экспорт в 1С / OFD** — позже, в админке только базовая выгрузка.
- **Мультиресторан / франшиза** — архитектура поддерживает (есть `restaurantId`), UI — позже.
- **Облачная синхронизация / дашборд для владельца удалённо** — отдельная фаза.
- **Эквайринг банковской картой через POS-приложение** — интеграция с банком отдельно.
- **Резервирование столиков клиентом онлайн** — отдельный продукт.

## 14. Риски

| Риск | Вероятность | Митигация |
|---|:---:|---|
| Принтер не работает с кириллицей | средняя | Тест на старте; запас — транслит/ESC/POS-настройки |

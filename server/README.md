# Restaurant Server (Dart Frog)

Локальный POS-сервер, который запускается на одной машине внутри
ресторана и связывает между собой:

- POS-приложение (официанты / касса / кухня),
- веб-страницу QR-меню для клиентов.

## Стек

- **Dart Frog** — REST-фреймворк (роуты как файлы в `routes/`).
- **SQLite** через `package:sqlite3` — встроенная база, ничего отдельно
  поднимать не нужно.
- **WebSocket** (`dart_frog_web_socket`) — push событий всем клиентам
  в реальном времени.

## Быстрый старт

```bash
# из корня репо
cd server

# 1. Поставить CLI dart_frog (один раз)
dart pub global activate dart_frog_cli

# 2. Поставить зависимости
dart pub get

# 3. Запустить dev-сервер
#    Порт 8080 у Windows часто занят WSL/IIS, поэтому используем 8765.
dart_frog dev --port 8765
```

> Если 8765 у вас тоже занят — выберите любой свободный, например 9000.
> Проверить, кто слушает порт, можно так:
> `Get-NetTCPConnection -LocalPort 8080 -State Listen | % { Get-Process -Id $_.OwningProcess }`

При первом запуске будет создан файл базы данных
`server/.data/restaurant.db` с миграциями и сидами:

- 1 ресторан, 1 зал, 5 столиков,
- 4 категории и 8 блюд для теста,
- 3 пользователя: `admin`, `waiter1`, `cook1` (пароль у всех `1234`).

## Конфигурация (env)

| Переменная       | Значение по умолчанию          | Назначение                                          |
|------------------|--------------------------------|-----------------------------------------------------|
| `PORT`           | `8080`                         | Порт HTTP сервера (передаётся `dart_frog`)          |
| `DB_PATH`        | `.data/restaurant.db`          | Путь к SQLite файлу                                 |
| `ADMIN_PASSWORD` | `1234`                         | Пароль admin при первом старте                      |

## Эндпоинты

### Авторизация

| Метод | Путь                | Кто          | Назначение                          |
|-------|---------------------|--------------|-------------------------------------|
| POST  | `/api/auth/login`   | все          | Логин по `username`+`password`      |

### Меню (только чтение)

| Метод | Путь                  | Кто          | Назначение                          |
|-------|-----------------------|--------------|-------------------------------------|
| GET   | `/api/menu`           | все, в т.ч. QR | Категории + блюда                  |
| GET   | `/api/halls`          | сотрудники   | Список залов (табы карты зала)      |
| GET   | `/api/tables`         | сотрудники   | Список столиков с статусами         |
| GET   | `/api/tables/by-qr/:token` | QR-клиент | Получить столик по QR-токену        |

### Заказы

| Метод | Путь                                | Кто        | Назначение                                |
|-------|-------------------------------------|------------|-------------------------------------------|
| GET   | `/api/orders`                       | сотрудники | Активные заказы                            |
| GET   | `/api/orders/:id`                   | сотрудники | Один заказ с позициями                     |
| POST  | `/api/orders`                       | официант   | Создать новый заказ для стола              |
| PATCH | `/api/orders/:id`                   | официант   | Обновить заказ (`guestsCount`)             |
| POST  | `/api/orders/:id/items`             | официант   | Добавить позицию в открытый заказ          |
| DELETE| `/api/orders/:id/items/:itemId`     | официант   | Удалить черновую позицию (draft)           |
| POST  | `/api/orders/:id/send`              | официант   | Отправить непосланные позиции на кухню     |
| PATCH | `/api/orders/:id/items/:itemId/status` | повар   | Изменить статус позиции (cooking/ready)    |
| POST  | `/api/orders/:id/pay`               | кассир     | Принять оплату                             |

### Предзаказ от клиента (QR)

| Метод | Путь                  | Кто       | Назначение                                                          |
|-------|-----------------------|-----------|---------------------------------------------------------------------|
| POST  | `/api/preorders`      | QR-клиент | Клиент отправляет корзину; официант увидит для подтверждения        |

### QR-коды (печать стикеров)

| Метод | Путь                                | Кто   | Назначение                                                  |
|-------|-------------------------------------|-------|-------------------------------------------------------------|
| GET   | `/api/qr/<token>.png?size=512`      | все   | PNG QR-код для конкретного столика. URL внутри QR строится из `Host`/`X-Forwarded-Host`. |
| GET   | `/api/admin/qr-poster?base=...`     | админ | HTML-страница со всеми QR, удобно печатать (`Ctrl+P`).       |

### Real-time

| Путь  | Назначение                                                |
|-------|-----------------------------------------------------------|
| `/ws` | WebSocket. Сервер шлёт `WsEvent`-сообщения (см. `shared_models/events.dart`). |

### Статика (Flutter Web)

Содержимое папки `server/public/` отдаётся по корню — туда копируется
собранное QR-меню (`client_menu/build/web/`). Скрипт
`scripts/build_and_run.ps1` делает это автоматически.

## Структура каталога

```
server/
├── public/                   — сюда копируется Flutter Web build, отдаётся по `/`
├── routes/                   — файлы-роуты Dart Frog
│   ├── _middleware.dart      — CORS для API, пропуск статики, бинарные ответы
│   ├── ws.dart               — WebSocket
│   └── api/
│       ├── admin/qr-poster.dart    — печатный лист QR (HTML)
│       ├── auth/login.dart
│       ├── menu/index.dart
│       ├── preorders/index.dart
│       ├── qr/[token].dart         — PNG QR-кода для столика
│       ├── tables/index.dart
│       ├── tables/by-qr/[token].dart
│       └── orders/
│           ├── index.dart
│           └── [id]/
│               ├── send.dart
│               ├── items/index.dart
│               ├── items/[itemId]/status.dart
│               └── pay.dart
└── lib/
    └── src/
        ├── app_context.dart  — синглтоны (БД, шина событий)
        ├── database.dart     — миграции и подключение
        ├── event_bus.dart    — рассылка WS-сообщений
        ├── qr_renderer.dart  — рендер QR в PNG
        ├── seed.dart         — данные первого запуска
        ├── auth.dart         — хеширование, токены, гарды
        └── repositories/
            ├── menu_repository.dart
            ├── orders_repository.dart
            ├── tables_repository.dart
            └── users_repository.dart
```

## Запуск всей системы одной командой

См. [docs/DEPLOY.md](../docs/DEPLOY.md). Кратко:

```powershell
# Из корня репозитория. Собирает Flutter Web → копирует в public/ → запускает.
./scripts/build_and_run.ps1

# Один раз — открыть порт в Windows Firewall (нужны права администратора).
./scripts/open_firewall.ps1 -Port 8765
```
